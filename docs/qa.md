## A. Продукт і контент

### A1. Напрямок перекладу
**Статус:** Узгоджено

- Цільова мова учня в MVP — англійська; переклад **UA→EN**.
- Source завжди українська.
- Обидва напрямки в одній вправі не потрібні.

### A2. Одна мова чи платформа мов
**Статус:** Узгоджено

- Модель **без прив’язки** до конкретних мов (`sourceLang` / `targetLang`).
- Інших мов у перший рік не буде; MVP-контент лише UA→EN.

### A3. Формат статті
**Статус:** Узгоджено

- WYSIWYG (HTML у БД, не Markdown).
- Зображення, таблиці, аудіо — так.
- Рендер на UI (з санітизацією).

### A4. Зв’язок статті і вікторини
**Статус:** Узгоджено

- Багато вправ на один урок.
- Вікторину можна проходити без читання статті.
- Подію «статтю переглянуто» не фіксуємо.

### A5. Банк слів і дистрактори
**Статус:** Узгоджено

- Дистрактори на старті вводить Manager (3 на токен).
- Токен може бути словосполученням, не лише словом через пробіл.
- Регістр і апострофи зберігаються в канонічній відповіді (для показу та diff).

### A6. Перевірка вільної відповіді
**Статус:** Узгоджено

- Порівняння після нормалізації (пробіли) + **ігнор пунктуації** + список **синонімів**.
- Апостроф у скороченнях не вважаємо «пунктуацією для видалення».
- Після помилки показуємо **diff** з каноном.

### A7. Ліміти Standard vs Premium
**Статус:** Узгоджено

- Платне: **повний доступ до вправ**.
- Standard: лише **перші 10 питань** пулу вправ уроку (усі 3 рівні складності доступні).
- Premium — **підписка** з датою закінчення, не лише прапорець ролі.

### A8. Платежі
**Статус:** Узгоджено

- У MVP Premium видає **Admin** на email реєстрації.
- Платіжний шлюз — після MVP.

## B. Користувачі, безпека, доступ

### B1. Реєстрація
**Статус:** Узгоджено (частково)

- Вхід через **OAuth**.
- Підтвердження email до вікторини не потрібне.
- GDPR: згода та право на видалення даних.

**Ще відкрито:** які саме провайдери в MVP (Google / Microsoft / Apple / кілька)?

### B2. Сесія
**Статус:** Узгоджено

- **BFF**, cookie-only, токен не в браузері.
- Refresh / сесія: **30 днів**.
- Відкликання всіх сесій при GDPR-видаленні акаунта — обов’язкове (випливає з D3).

### B3. Матриця ролей
**Статус:** Узгоджено

- Manager бачить **усі** уроки.
- Manager **не** бачить ПІБ учнів — лише агрегати.
- Мінімум **1** Admin; супер-адмін поза Identity не потрібен.
- Standard/Premium — ролі **і** права на матеріали; повний доступ до вправ додатково вимагає активної `Subscription`.

### B4. Анонімний доступ
**Статус:** Узгоджено (частково)

- Статті доступні всім (включно з анонімами).
- Демо-вікторина — так.

**Ще відкрито:** чи писати анонімні спроби демо і чи мерджити їх після OAuth?

### B5. Адмін-зона
**Статус:** Узгоджено

- `/admin` у тому ж Angular.
- Окремий SPA не потрібен.

## D. Статистика та аналітика

### D1. Особистий прогрес
**Статус:** Узгоджено

- Питання у **випадковому** порядку, **безперервно**.
- Успіх = **% з останніх 100** відповідей.
- Окремий прогрес **на кожен рівень** складності.
- Streak не робимо.

### D2. Продуктова аналітика
**Статус:** Узгоджено

Обов’язково в MVP:

- DAU/WAU, нові реєстрації.
- % успішних спроб по вправі та уроку.
- Кількість користувачів Standard і **активних** Premium-підписок.

Не робимо: воронка стаття→вікторина, час на відповідь.

### D3. Зберігання сирих подій
**Статус:** Узгоджено (частково)

- Право на видалення персональних даних — **так**.
- Сирі спроби в MVP тримаємо в SQL (таблиця `QuizAttempt`); окремий event stream не закладаємо, доки не скажуть інакше.

**Ще відкрито:** скільки зберігати сирі спроби (безстроково / N місяців), якщо користувач **не** просить erase?

## G. Стиль Application

### G1. CQRS і MediatR
**Статус:** Узгоджено (2026-10-06)

- У `Training.Application` — **логічний CQRS + MediatR**.
- **Одна** PostgreSQL, один `DbContext`. Окремої read-БД, шини подій і event sourcing немає.
- Query не змінює стан і не віддає канон відповіді. Command змінює стан; `SubmitAttempt` + прогрес — **одна транзакція**.
- Нових `I{Name}Service` у Domain не додаємо.

### G2. Репозиторій vs `ITrainingDbContext`
**Статус:** Узгоджено (2026-10-06)

- За замовчуванням: **`ITrainingDbContext` + хендлери MediatR**. Один `TrainingDbContext` реалізує інтерфейс.
- **Не** розмножувати `I{Name}Repository` у Domain. Generic CRUD-репозиторій не є стандартом.
- Вузький доступ за змістом (`IQuestionPicker`, не `*Repository`) — лише для повторюваного або важкого запиту.
- `IExerciseRepository` — спадок in-memory прототипу, не вимога CQRS.
